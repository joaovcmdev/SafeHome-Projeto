# ADR-0003 — Criação do Diagrama de Componentes

## Contexto

Neste documento, será analisado o componente Device_service, responsável pelo controle dos dispositivos. A análise apresenta um modelo em Mermaid que representa o componente e suas principais conexões com outras partes do sistema.

## Componentes e responsabilidades

### Device_service
Responsável por receber e executar comandos destinados aos dispositivos do sistema.

### InMemoryRepository
Responsável pelo armazenamento e busca dos dispositivos cadastrados.

### AcmeHomeLegacyApi
Responsável pela comunicação com dispositivos do fabricante ACME.

### ZenIoTLegacyApi
Responsável pela comunicação com dispositivos do fabricante ZEN.

### HomePublisher
Responsável pela publicação de eventos relacionados às operações realizadas.

---

## Conectores e evidências no código

### Device_service → InMemoryRepository

O `Device_service` utiliza o repositório para localizar o dispositivo que receberá o comando.

```java
Device d = devices.find(deviceId);
```

### Device_service → AcmeHomeLegacyApi

Quando o dispositivo pertence ao fabricante ACME, o serviço utiliza a API correspondente enviar o comando.

```java
if("ACME".equals(d.manufacturer)){
    acme.execute(deviceId, command);
}
```

### Device_service → ZenIoTLegacyApi

Quando o dispositivo pertence ao fabricante ZEN, o serviço utiliza a API correspondente para enviar o comando.

```java
else if("ZEN".equals(d.manufacturer)){
    zen.sendCommand(deviceId, "ON".equals(command) ? 1 : 0);
}
```

### Device_service → HomePublisher

Após a execução do comando, o serviço publica um evento informando a ação realizada.

```java
publisher.publish(deviceId, "COMMAND_EXECUTED");
```

---

## Justificativa técnica

A separação do `Device_service` permite concentrar a responsabilidade de controle dos dispositivos em um componente específico.

Essa organização facilita o entendimento e a manutenção do código, além de separar a comunicação com diferentes fabricantes do restante das funcionalidades do sistema SafeHome.
